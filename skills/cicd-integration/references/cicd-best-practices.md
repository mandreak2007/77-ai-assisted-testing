# CI/CD Best Practices

Apply every rule in this file to every pipeline config generated by the cicd-integration skill.

---

## Secrets & Environment Variables

- **Never hardcode** URLs, emails, passwords, tokens, or API keys in pipeline files
- All sensitive values must come from the platform's secret/variable store:
  - GitHub Actions: `${{ secrets.SECRET_NAME }}`
  - GitLab CI: `$SECRET_NAME` (set in CI/CD Variables, masked)
  - Jenkins: `credentials('CREDENTIAL_ID')`
  - Azure DevOps: `$(VARIABLE_NAME)` (set in Variable Groups, marked secret)
  - CircleCI: `$ENV_VAR_NAME` (set in Project Settings → Environment Variables)
  - Bitbucket: `$ENV_VAR_NAME` (set in Repository Variables)
- Always read `.env.example` to identify all variables that need to be added as secrets
- Minimum required secrets for every project:
  - `BASE_URL` — the application under test's base URL
  - `TEST_USER_EMAIL` — test account credential
  - `TEST_USER_PASSWORD` — test account credential

---

## Caching

- **Always cache `node_modules` / `.npm`** — reduces install time from ~60s to ~5s
  - Cache key: hash of `package-lock.json` so the cache invalidates when deps change
- **Always cache Playwright browser binaries** (`~/.cache/ms-playwright` or `$PLAYWRIGHT_BROWSERS_PATH`)
  - Cache key: `playwright-<os>-<hash of package-lock.json>`
  - When using the official `mcr.microsoft.com/playwright` Docker image, browsers are pre-installed — skip the browser cache and the install step
- After a cache hit on browsers, still run `npx playwright install-deps <browser>` to install OS-level system dependencies (they are not cached)

---

## Browser Selection

- **Default in CI: chromium only** — fastest, most stable in headless environments
- Add `firefox` or `webkit` only if the user explicitly asks for cross-browser CI
- To run multiple browsers, add them to the install command: `npx playwright install chromium firefox`
- Never run headed mode in CI — all runs must be headless

---

## Parallel Sharding (CLI Mode)

- **Default: 4 shards** for CLI mode unless the user specifies a different count
- Each shard runs a subset of tests: `npx playwright test --shard=N/TOTAL`
- After all shards complete, merge blob reports: `npx playwright merge-reports --reporter html ./blob-report`
- Requires Playwright v1.38 or later
- For very small test suites (< 10 tests), sharding adds overhead — disable it and run single-job

---

## Parallel Jobs (MCP/BDD Mode)

- Cucumber does not natively support `--shard`
- For BDD parallelism, use the platform's native parallel jobs (GitLab `parallel:`, Bitbucket `parallel:`, etc.)
- Each job runs the full suite or a tagged subset: `npx cucumber-js --tags "@smoke"` and `npx cucumber-js --tags "@regression"`
- Default: single job (no sharding) unless the user asks for parallel BDD execution

---

## Artifacts & Reporting

- **Always upload test reports as artifacts**, even (especially) on failure
- CLI mode: upload `playwright-report/` (HTML), `blob-report/` (for merging), `test-results/` (screenshots/videos on failure)
- MCP/BDD mode: upload `reports/` directory
- Set artifact retention:
  - Shard blob reports: 1 day (temporary, only needed for merge step)
  - Final HTML report: 30 days
- Where supported, use `expose_as` or equivalent to surface the report link in the pipeline UI

---

## Timeouts

- **Set a 60-minute job-level timeout** to prevent runaway pipelines from consuming build minutes
- Add a `timeout-minutes: 60` (GitHub Actions), `timeout: 3600` (GitLab), or `timeout(60, 'MINUTES')` (Jenkins) to every job

---

## Triggers

- Default triggers for every pipeline:
  - Push to `main`
  - Push to `develop`
  - Pull requests / merge requests targeting `main` or `develop`
  - Manual trigger (workflow_dispatch / web UI button)
- Never trigger on every branch by default — this wastes build minutes
- Do not add scheduled triggers unless the user explicitly asks for nightly runs

---

## Docker Image Version Pinning

- When using `mcr.microsoft.com/playwright`, always pin to a specific version tag (e.g., `v1.50.0-noble`)
- Never use `latest` — it changes silently and can break pipelines
- The image tag version must match the `@playwright/test` version in `package.json`
- Check the current version with: `npx playwright --version`

---

## Checklist — Apply Before Every Config is Written

```
[ ] No hardcoded secrets — all from secret store
[ ] node_modules / .npm cache configured with package-lock.json key
[ ] Playwright browser cache configured (or Docker image used)
[ ] Chromium-only install unless user requests more browsers
[ ] 60-minute job timeout set
[ ] Artifacts uploaded on success AND failure (if: always / when: always)
[ ] Artifact retention: blob=1 day, HTML report=30 days
[ ] Triggers: push to main + develop, PRs, manual
[ ] Docker image version pinned (if applicable)
[ ] Test runner command matches detected mode (cucumber-js vs playwright test)
[ ] Report path matches mode (reports/ vs playwright-report/)
```
