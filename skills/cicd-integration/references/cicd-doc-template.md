## Troubleshooting

### Pipeline fails immediately — `npm ci` error

**Cause:** `package-lock.json` is out of sync with `package.json`.
**Fix:** Run `npm install` locally, commit the updated `package-lock.json`, and push.

### `Browser was not found` error

**Cause:** Playwright browser cache miss and install step failed.
**Fix:** Clear the browser cache key in your platform's cache settings and re-run.
The pipeline will reinstall browsers from scratch.

### Tests time out in CI but pass locally

**Cause:** CI machines are slower; default Playwright timeouts may be too tight.
**Fix:** Increase the `timeout` in `playwright.config.ts`:
```typescript
use: {
  actionTimeout: 30_000,
  navigationTimeout: 60_000,
}
```

### `Secret not found` / environment variable is undefined

**Cause:** A required secret was not added to the platform's secret store.
**Fix:** Follow the "How to Add Secrets" section above. Secret names are case-sensitive.

### All shards fail with the same error

**Cause:** A global setup issue (e.g., app is unreachable, wrong `BASE_URL`).
**Fix:** Verify the `BASE_URL` secret points to a reachable environment. Check
`global-setup.ts` logs in the artifact output.

### MCP/BDD: `cucumber-js: command not found`

**Cause:** `npm ci` did not install devDependencies.
**Fix:** Ensure `@cucumber/cucumber` is in `devDependencies` in `package.json`,
not `dependencies`. Re-run the pipeline.

### GitHub Actions

**`<PIPELINE_STAGES_SECTION>`**
```
The pipeline is defined in `.github/workflows/playwright.yml` and consists of
two jobs:

**Job: test (runs in parallel across 4 shards)**
- Checkout repository
- Set up Node.js 20 with npm cache
- Restore Playwright browser cache
- Install dependencies (`npm ci`)
- Install Playwright browsers (if cache miss)
- Run tests for this shard
- Upload blob report artifact

**Job: merge-reports (runs after all shards complete)**
- Download all blob report artifacts
- Merge into a single HTML report
- Upload final HTML report artifact
```

**`<STAGES_EXPLANATION_SECTION>`**
```
1. **Checkout** — Pulls the latest code from the branch that triggered the run.
2. **Set up Node.js** — Installs Node 20 and restores the npm cache keyed to `package-lock.json`.
3. **Restore browser cache** — Reuses the Playwright browser binaries from a previous run if `package-lock.json` has not changed. Saves ~2 minutes per shard.
4. **npm ci** — Installs exact dependency versions from `package-lock.json`. Faster and more deterministic than `npm install`.
5. **Install browsers** — Only runs on a cache miss. Downloads Chromium and its system dependencies.
6. **Run tests** — Executes one quarter of the test suite. Each shard runs independently in parallel.
7. **Upload blob report** — Saves raw test results for the merge job. Retained for 1 day.
8. **Merge reports** — Combines all 4 shard results into one HTML report. Retained for 30 days.
```

**`<SECRETS_SETUP_INSTRUCTIONS>`**
```
1. Go to your GitHub repository.
2. Click **Settings** → **Secrets and variables** → **Actions**.
3. Click **New repository secret**.
4. Enter the secret name (e.g., `BASE_URL`) and its value.
5. Click **Add secret**.
6. Repeat for each secret in the table above.
```

**`<TRIGGER_INSTRUCTIONS>`**
```
The pipeline triggers automatically on:
- **Push** to `main` or `develop` branches
- **Pull request** targeting `main` or `develop`

To trigger manually:
1. Go to your repository on GitHub.
2. Click the **Actions** tab.
3. Select **Playwright Tests** from the left sidebar.
4. Click **Run workflow** → choose a branch → **Run workflow**.
```

**`<ARTIFACTS_SECTION>`**
```
- **blob-report-1 through blob-report-4** — Raw shard results (1-day retention, auto-deleted after merge)
- **playwright-html-report** — Merged HTML report with test results, screenshots on failure, and traces (30-day retention)
```

**`<REPORT_VIEWING_INSTRUCTIONS>`**
```
1. Go to your repository → **Actions** tab.
2. Click the completed workflow run.
3. Scroll to the **Artifacts** section at the bottom.
4. Download **playwright-html-report** and open `index.html` in a browser.
```

**`<SHARDING_CUSTOMISATION>`**
```
Edit `.github/workflows/playwright.yml` and change the matrix values:

  matrix:
    shardIndex: [1, 2, 3, 4]   ← change count here
    shardTotal: [4]             ← must match the length of shardIndex
```

**`<SCHEDULED_RUN_INSTRUCTIONS>`**
```
Add a `schedule` trigger to `.github/workflows/playwright.yml`:

  on:
    schedule:
      - cron: '0 2 * * *'   # runs every day at 02:00 UTC
```

### Jenkins

**`<PIPELINE_STAGES_SECTION>`**
```
The pipeline is defined in `Jenkinsfile` at the project root as a declarative pipeline with three stages:

1. **Install dependencies** — `npm ci`
2. **Install Playwright browsers** — `npx playwright install chromium`
3. **Run tests** — `npx playwright test` (CLI) or `npx cucumber-js` (BDD), followed by HTML report publishing
```

**`<STAGES_EXPLANATION_SECTION>`**
```
1. **Agent** — Spins up a Docker container from the official Playwright image (`mcr.microsoft.com/playwright`). The `--ipc=host` flag is required for Chromium to run correctly.
2. **Install dependencies** — Runs `npm ci` with a local npm cache to speed up dependency resolution.
3. **Install browsers** — Installs Chromium inside the Docker container.
4. **Run tests** — Executes the full test suite. The `publishHTML` post step publishes the HTML report directly in the Jenkins build UI.
5. **Post actions** — Archives all report files and cleans the workspace regardless of pass/fail.
```

**`<SECRETS_SETUP_INSTRUCTIONS>`**
```
1. Go to **Manage Jenkins** → **Credentials** → **System** → **Global credentials**.
2. Click **Add Credentials**.
3. Choose **Secret text** as the kind.
4. Enter the credential ID (e.g., `PLAYWRIGHT_BASE_URL`) and the secret value.
5. Click **Create**.
6. Repeat for each credential in the table above.

These are referenced in the Jenkinsfile with `credentials('CREDENTIAL_ID')`.
```

**`<TRIGGER_INSTRUCTIONS>`**
```
The pipeline is triggered by:
- SCM polling (if configured in the Jenkins job)
- Webhooks from your Git host (recommended — configure in the Jenkins job → Build Triggers → GitHub/GitLab hook trigger)
- Manual trigger: click **Build Now** on the Jenkins job page.
```

**`<ARTIFACTS_SECTION>`**
```
- **Playwright HTML Report** — Published via `publishHTML` and accessible directly from the Jenkins build page sidebar.
- **playwright-report/** — Archived as a build artifact, downloadable from the build page.
```

**`<REPORT_VIEWING_INSTRUCTIONS>`**
```
1. Go to the Jenkins job page.
2. Click the completed build number.
3. Click **Playwright HTML Report** in the left sidebar (published by the HTML Publisher Plugin).
```

**`<SHARDING_CUSTOMISATION>`**
```
To add sharding in Jenkins, replace the single "Run tests" stage with a parallel block:

  stage('Run tests') {
    parallel {
      stage('Shard 1') { steps { sh 'npx playwright test --shard=1/4' } }
      stage('Shard 2') { steps { sh 'npx playwright test --shard=2/4' } }
      stage('Shard 3') { steps { sh 'npx playwright test --shard=3/4' } }
      stage('Shard 4') { steps { sh 'npx playwright test --shard=4/4' } }
    }
  }

Add a downstream merge job that runs `npx playwright merge-reports` after all shards complete.
```

**`<SCHEDULED_RUN_INSTRUCTIONS>`**
```
In the Jenkins job configuration, go to **Build Triggers** → check **Build periodically**
and enter a cron expression (e.g., `H 2 * * *` for roughly 02:00 daily).
```

### Azure DevOps

**`<PIPELINE_STAGES_SECTION>`**
```
The pipeline is defined in `azure-pipelines.yml` as a single-stage pipeline with a
parallel job strategy (4 agents run simultaneously, each handling one shard of tests).
```

**`<STAGES_EXPLANATION_SECTION>`**
```
1. **Install Node.js** — Uses the NodeTool task to install Node 20.
2. **Cache npm packages** — Caches `.npm` keyed to `package-lock.json`.
3. **Cache Playwright browsers** — Caches the browser binaries separately.
4. **npm ci** — Installs exact dependency versions.
5. **Install browsers** — Installs Chromium.
6. **Run tests** — Each of the 4 parallel agents runs `npx playwright test --shard=<agent-index>/4` automatically via `System.JobPositionInPhase`.
7. **Publish test results** — Uploads JUnit XML results to the Azure DevOps test tab.
8. **Publish artifacts** — Uploads the HTML report for each shard.
```

**`<SECRETS_SETUP_INSTRUCTIONS>`**
```
1. Go to **Pipelines** → **Library** → **+ Variable group**.
2. Create a group (e.g., `playwright-secrets`).
3. Add each variable (e.g., `BASE_URL`). Click the padlock icon to mark sensitive values as secret.
4. Save the group.
5. In `azure-pipelines.yml`, link the group:

   variables:
     - group: playwright-secrets
```

**`<TRIGGER_INSTRUCTIONS>`**
```
The pipeline triggers automatically on:
- Push to `main` or `develop`
- Pull requests targeting `main` or `develop`

To trigger manually:
1. Go to **Pipelines** → select your pipeline.
2. Click **Run pipeline** → choose a branch → **Run**.
```

**`<ARTIFACTS_SECTION>`**
```
- **playwright-report-N** — One artifact per shard containing the shard's HTML report.
- **Test Results tab** — JUnit XML results are parsed and displayed natively in the Azure DevOps build summary.
```

**`<REPORT_VIEWING_INSTRUCTIONS>`**
```
1. Go to **Pipelines** → click the completed run.
2. Click the **Tests** tab to see pass/fail counts and individual test results.
3. Click **Artifacts** to download the HTML report for any shard.
```

**`<SHARDING_CUSTOMISATION>`**
```
Change the `parallel: 4` value in `azure-pipelines.yml` to your desired shard count.
Azure DevOps automatically distributes `System.JobPositionInPhase` across all agents.
```

**`<SCHEDULED_RUN_INSTRUCTIONS>`**
```
Add a `schedules` section to `azure-pipelines.yml`:

  schedules:
    - cron: "0 2 * * *"
      displayName: Nightly run
      branches:
        include:
          - main
      always: true
```
